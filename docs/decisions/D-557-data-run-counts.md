# D-557 · Data run: margins and counts for ACS maps

- **PR:** #457 (closes #454). Extends D-478 (the Data run) and D-552. Unblocks #188 (real margins on change maps).

**Problem.** The earlier-year margins (`values/<id>/<stop>/<level>.moe.json`, D-257) were never published: `ingest counts` writes them, but it ran only on Robbie's machine, and the Data run refused `counts` (listed as needing GDAL or tippecanoe). So `values/median_household_income/2019/county.moe.json` is a 404 while `2019/county.json` is live.

**What `counts` needs, for ACS maps.** `CENSUS_API_KEY`, `SUPABASE_DB_URL` (read only: land areas from `geographies`), and downloads it caches itself (2019 Gazetteer files for pre-2020 periods, the 2024 block-group shapefile's `.dbf` for block-group land area, read in JS). No GDAL, no tippecanoe, no local tiles: with nothing on disk, its tract and block-group shards hold only the series it just loaded. Non-ACS sources (census2020, ddp287g, LODES, FARS, TRI) aren't needed for #188 and stay local.

**Decided.** A new step value `counts`, allowed only alone (like `features`), and only for `acs5` maps (`data/ingest/src/check-run.ts`). The run does `ingest counts <ids>` (writes margins for every period, the default period's counts files and U.S. rows, and the count shards; no database writes, no value files) instead of the loads and `export-values`. The rest is the same as a load: `details`, `similar`, then `publish-reload`, `publish-details` and `publish-similar`. `similar` reads `population_density`'s `county.counts.json`, which a counts run rewrites when that id is named, so it must run too; `details` runs because `similar` reads its files. Unchanged details are skipped on upload (ETag match).

**One mode, decided once.** `check-run` writes `mode` (`values`, `features`, `counts` or `export-values`) to `GITHUB_OUTPUT`, and every step in `data-run.yml` is gated on `steps.check.outputs.mode`. "Load and export" picks the commands for the mode inside its script, and there is one "Publish to R2" step for every mode but `features`. Because the mode comes from the words, not the raw input, stray spaces around `features` or `counts` no longer matter, so the "type it exactly" check is gone.

**Why it can't shrink live data.** `publish-reload` merges each local shard (`values/counts/tract|block_group/<county>.json`) into the live one, swapping in only the reloaded series, and stops before any upload if a county would lose one, including live counties this run wrote no file for. Then `publishJson`'s `uploadProblems` re-checks every changed shard against R2. `ALLOW_TRACT_DROP` is set only from the run's input. Ids are required: an empty `datasets` would run every source, so it's refused.

**Margins and counts are drop-checked too.** `uploadProblems` now treats a map's `[<stop>/]{state,county,tract}.moe.json` and `{state,county}.counts.json` like its `state.json` and `county.json`: fewer places than the live file refuses the whole upload, unless `ALLOW_TRACT_DROP=1`. The patterns are the same ones `publish-counts` uses (`MOE_FILE`, `COUNTS_FILE` in `publish-tiles.ts`), so the two can't disagree. This also covers a local `publish-counts`. So a short Census response can't shrink a live margin file.

**Limits.** `us.json` (one row) isn't drop-checked. `ALLOW_TRACT_DROP` is one switch for every check: ticking it for a real tract loss also lets a short margin or counts file through, so read the refused run's whole list first. A parts set's remainder series is rewritten only when every member is named; otherwise the live one is kept by the merge.
