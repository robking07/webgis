# D-198 · Static click details

- **Date:** 2026-10-06
- **Status:** DEFAULTED (worker, roadmap task S1, issue #94; storage on R2 per Robbie's data pause of 2026-10-05)
- **PR:** #98

**Problem.** Every state or county click on `/map` and every state or county place page queried
Supabase from the visitor's browser (`dataset_values`, and `geographies` on place pages). At scale
that is the first thing to fail on the free tier, and a paused database broke the details panel.

**Decided.**

1. **Layout: one file per state**, `details/<state fips>.json`, holding the state and its counties:
   `{ "<geoid>": { name, lon, lat, aland_sqmi, values: { "<dataset id>": [value, moe] } } }`.
   One fetch serves a state click, any of its counties, and their place pages (cached per page view).
   52 files (50 states, DC, Puerto Rico), 3,274 places, 186,697 values from 58 datasets:
   9.1 MB raw, **2.74 MB gzipped** in total. The largest is Texas (705 KB raw, 215 KB gzipped);
   Minnesota is 74 KB gzipped. Per-place files (3,274) would be smaller per click but far more
   objects; one national file would be 2.7 MB per click. Values are copied exactly (no rounding), so
   the panel and place pages show the same numbers as the database did.
2. **Where: R2, beside the block-group values** (D-124), `https://tiles.mapwich.org/details/…`,
   gzip-encoded, `Cache-Control: public, max-age=3600`. The web reads them from
   `NEXT_PUBLIC_TILES_BASE_URL` (the `/tiles` link to `data/tiles` in local dev). Nothing new goes
   into `apps/web/public/data` (data pause until S2).
3. **Regenerated by the ingest pipeline:** `npm run ingest -- details` writes `data/tiles/details/`
   from the database's state and county rows (`dataset_values`, `geographies`);
   `npm run ingest -- publish-details` uploads them. `ingest all` runs `details`; after any single
   dataset ingest, run both (the `add-dataset` skill says so). The database stays the ingest store.
4. **Web:** `apps/web/src/lib/details.ts` now holds `fetchDetail` (states and counties from the
   R2 file; tracts still from `values/tracts/<county>.json`, D-113) and `fetchGeography` (states and
   counties from the R2 file). `lib/supabase.ts` keeps only the client (keep-alive, tract geography).
5. **Test runner: Vitest** at the repo root (`npm test`, `vitest.config.ts`, files
   `**/src/**/*.test.ts` in `apps`, `packages` and `data`). It runs TypeScript and the web's `@/`
   alias with no build step, in under a second. CI runs it in the `lint` job after ESLint, so it
   shares that job's `npm ci` rather than paying for another runner.
6. **E2E:** `menus.spec.mjs` gains "static details" at phone and laptop sizes: click a county and a
   state, open `/place/27053` and `/place/27`, and fail on any request to the Supabase host.

**Not changed.** Tract place pages still read tract geography (name, centroid, land area) from
Supabase; the details panel never needed it. Supabase tables, migrations and the keep-alive cron
are untouched. `ingest run` now also loads the main checkout's `.env.local` when run from a worktree
that has none (the variables are never printed).

**Checked.** Live mapwich.org and this build gave identical text for `/place/27053`, `/place/27` and
the Hennepin and Minnesota details panels at phone and laptop sizes (58 datasets, every value and
margin of error); the local build made no Supabase request.
